## Chapter 1: Cloud Identity, SSO, and Workforce Identity Federation — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Cloud Identity Free edition user limit? | 50 users maximum. Exam tip: need more users or advanced security/endpoint features → Cloud Identity Premium (no user cap). |
| 2 | Enforceable password length range in Admin console? | 8–100 characters. Exam tip: also configure password reuse prevention and expiration under Security > Password management. |
| 3 | Max Google session length configurable for web sessions? | Up to 24 hours, or set to 'never expire'. Configured under Security > Google session control. Shorter sessions reduce stolen-cookie risk. |
| 4 | Workforce Identity Federation vs Workload Identity Federation — key difference? | Workforce = human users authenticating via external IdP (SAML/OIDC) to access GCP without a Cloud Identity account. Workload = external machine/service identities (AWS, on-prem, other clouds) accessing GCP APIs without SA keys. Mnemonic: workforce = people, workload = machines. |
| 5 | SAML SSO with third-party IdP vs Workforce Identity Federation for Cloud Identity? | SAML SSO requires the user to already exist as a Cloud Identity/Workspace account (federated login maps to that existing object). WIF grants IAM access with NO Cloud Identity account created at all. If requirement says 'don't create Google accounts' → choose WIF. |
| 6 | Google Cloud Directory Sync (GCDS) — what does it do? | One-way sync tool that provisions/updates/deprovisions Cloud Identity users, groups, and attributes from on-prem LDAP/Active Directory. Runs on-prem/scheduled. Sync is one-directional: AD → Cloud Identity only, never the reverse. |
| 7 | Cloud Identity Free vs Premium — biggest exam differentiator? | Premium removes the 50-user cap and adds advanced endpoint (mobile device) management, enhanced security features, and SLA. Free is basic SSO/directory only, capped at 50 users. |
| 8 | Super-admin account hardening checklist (exam-tested items)? | 1) Dedicated super-admin account not used for daily email 2) Enforce 2-Step Verification, ideally security-key only 3) Use FIDO/physical security keys (e.g., Titan) 4) Enroll in Advanced Protection Program 5) Assign to individual accounts only, never a Group. |
| 9 | Can the super-admin role be assigned to a Google Group? | No. Admin roles, including super-admin, can only be assigned to individual user accounts. Any answer suggesting group assignment for 'easier management' is a trap. |
| 10 | Where is Workforce Identity Federation configured? | IAM > Workforce Identity Federation. Create a Workforce Identity Pool, add a Provider (SAML 2.0 or OIDC), define attribute mapping/condition, then grant IAM roles to principal://iam.googleapis.com/locations/global/workforcePools/POOL_ID/subject/SUBJECT. |
| 11 | Which external IdP protocols does Workforce Identity Federation support? | SAML 2.0 and OIDC (e.g., Okta, Azure AD/Entra ID, Ping, ADFS). No Cloud Identity/Workspace account is ever created for the authenticated user. |
| 12 | Typical CLI command to run a GCDS sync? | ./sync-cmd -a -c config.xml -l logfile.log — executes the GCDS configuration to sync AD/LDAP into Cloud Identity. GCDS is a downloadable tool run from an on-prem machine/VM with LDAP connectivity, not a hosted GCP service. |
