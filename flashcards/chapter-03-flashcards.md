## Chapter 3: IAM Authorization: Conditions, Deny Policies, and Org Policy — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Maximum custom roles per project or organization, and max permissions per custom role? | 300 custom roles per project/org; up to 3,000 permissions per custom role. Exam tip: custom roles CANNOT be created at the folder level — only project and organization. |
| 2 | Max duration of a Privileged Access Manager (PAM) grant? | Up to 14 days (2 weeks) per grant. Exam tip: PAM grants are time-bound, require an approval workflow, and auto-revoke at expiry with full audit logging. |
| 3 | IAM Condition vs IAM Deny Policy — when to use which? | Condition = attribute-based ALLOW restriction (time, resource tag/name) attached to a specific role binding. Deny Policy = explicit DENY that always overrides any allow, org-wide, regardless of role held. Use deny policy for guardrails that must never be bypassed. |
| 4 | Org Policy constraint vs IAM Deny Policy — what's the enforcement difference? | Org Policy governs which resource configurations/APIs are allowed (the resource). Deny Policy governs which principals can use which permissions (the identity). Org policies can be overridden at a lower hierarchy node by default; deny policies cannot be overridden by any allow policy. |
| 5 | Boolean constraint vs List constraint in Organization Policy? | Boolean = enforced true/false (e.g., constraints/iam.disableServiceAccountKeyCreation). List = allowed_values/denied_values array (e.g., constraints/gcp.resourceLocations). Exam tip: only list constraints support allow/deny value lists. |
| 6 | How do IAM allow policies behave across org > folder > project > resource? | Allow policies are additive/union — a role granted higher in the hierarchy is inherited at all descendants. A lower node CANNOT remove access granted above it; to restrict, you must use an explicit IAM Deny policy. |
| 7 | What attributes can an Access Context Manager Access Level evaluate? | IP subnet/range, device policy (managed device, encryption, OS), and geographic region/identity. Exam tip: Access Levels are consumed by Identity-Aware Proxy (app-level) and VPC Service Controls (perimeter-level) — NOT time of day. |
| 8 | gcloud command to view IAM deny policies attached to a resource? | gcloud iam policies list --attachment-point=<resource> --kind=denypolicies. Exam tip: deny policies use a separate Deny Policy API/CLI surface, not gcloud projects get-iam-policy. |
| 9 | CEL expression to allow access only until a specific date in an IAM condition? | request.time < timestamp("2026-12-31T00:00:00Z"). Exam tip: conditions use Common Expression Language (CEL); common attributes are request.time, resource.name, resource.type, resource.tag_keys/values. |
| 10 | Is there additional charge for using Policy Analyzer, Policy Simulator, or IAM Recommender? | No direct tool charge — they're included Policy Intelligence features (backed by Cloud Asset Inventory / audit logs, which have their own standard storage costs). Exam tip: don't pick 'too expensive' as the wrong answer for these tools. |
| 11 | Policy Analyzer vs Policy Simulator vs IAM Recommender — what does each do? | Analyzer = 'who has access to what resource today' (queries Cloud Asset Inventory). Simulator = tests a PROPOSED policy change before applying it, showing access impact. Recommender = suggests removing unused/overly-broad grants for least privilege. |
| 12 | How do you exempt a break-glass admin group from an org-wide IAM deny policy? | List the group in exceptionPrincipals (and/or exceptionPermissions) of the deny rule. Exam tip: deny policies support exceptions so you can enforce a guardrail for everyone except a designated emergency-access identity. |
