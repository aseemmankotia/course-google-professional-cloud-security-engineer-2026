## Chapter 4: Perimeter Controls: Cloud NGFW, IAP, and Cloud Armor — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What IP range must a VPC firewall rule allow to permit IAP TCP forwarding (SSH/RDP) to a VM? | 35.235.240.0/20. Exam tip: this is Google's IAP relay range — without an ingress allow rule for this range, IAP tunneling fails even if the user is authorized. |
| 2 | Priority range for hierarchical/network firewall policy rules vs legacy VPC firewall rules? | Hierarchical & network firewall policies: 0–2147483647. Legacy VPC firewall rules: 0–65535 (default 1000). Exam tip: lower number = higher priority in both. |
| 3 | Firewall evaluation order across tiers, from first to last? | 1) Hierarchical firewall policies (Organization → Folder) 2) Network firewall policies (global/regional) 3) VPC firewall rules (legacy). Exam tip: an explicit allow/deny without goto_next stops evaluation for that traffic. |
| 4 | Cloud NGFW tiers and what each adds | Essentials: basic L3–L4 filtering (network tags, service accounts). Standard: adds FQDN objects, geo-IP. Enterprise: adds Intrusion Prevention Service (IPS) and TLS inspection via threat intelligence. Exam tip: choose Enterprise when the scenario mentions IPS/signature-based threat detection. |
| 5 | Cloud Armor: Standard tier vs Managed Protection Plus tier | Standard: WAF rules, basic rate limiting, network/L7 DDoS defense. Managed Protection Plus: adds Adaptive Protection (ML-based anomaly detection), named IP address lists, and enhanced DDoS response support. Exam tip: 'ML-based/adaptive DDoS detection' in a question = Managed Protection Plus. |
| 6 | Cloud Armor rate limiting: throttle vs rate_based_ban | throttle: enforces the configured rate per interval, denies only requests over the limit. rate_based_ban: once threshold is exceeded, blocks the client for a configurable ban_duration_sec even below the threshold. Exam tip: 'block for X minutes after exceeding limit' = rate_based_ban. |
| 7 | Edge security policy vs backend (default) Cloud Armor security policy | Edge security policy: evaluated at Google's edge cache (Cloud CDN) before a request reaches the backend, protecting cached content. Backend security policy: evaluated on the backend service itself. Exam tip: edge policies exist specifically to protect CDN-cached responses. |
| 8 | Which load balancer type does IAP require for web (HTTPS) app access? | External Application Load Balancer (global, HTTPS) with IAP enabled on the backend service. Exam tip: IAP for TCP forwarding (SSH/RDP) works without a load balancer, using a direct tunnel instead. |
| 9 | Certificate Authority Service (CAS) tiers: DevOps vs Enterprise | DevOps tier: lightweight, short-lived certs, no CRL support — for high-volume automated issuance (e.g., service mesh). Enterprise tier: full PKI features including CRLs and longer-lived certs, policy controls. Exam tip: 'short-lived, high-volume, no revocation list needed' = DevOps tier. |
| 10 | Command to create a hierarchical firewall policy and attach it to an org node | gcloud compute firewall-policies create --organization=ORG_ID --short-name=POLICY_NAME gcloud compute firewall-policies associations create --firewall-policy=POLICY_NAME --organization=ORG_ID Exam tip: rules are added separately with `firewall-policies rules create --action=allow\|deny\|goto_next`. |
| 11 | What does DNSSEC actually protect, and what does it NOT do? | Protects: authenticates DNS responses (signed RRSIG/DNSKEY records) against spoofing/cache poisoning. Does NOT: encrypt query/response contents (that's DNS-over-HTTPS/TLS) or mitigate DDoS floods. Exam tip: DNSSEC = integrity/authenticity, not confidentiality. |
| 12 | Secure Web Proxy (SWP) — what problem does it solve? | Fully managed forward proxy that filters/allowlists outbound HTTP(S) traffic from VMs by FQDN/URL, without deploying and patching self-managed proxy instances. Exam tip: choose SWP over Cloud NAT when the requirement is domain-level egress filtering, not just address translation. |
