## Chapter 5: VPC Service Controls, Shared VPC, and Private Connectivity — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | VPC Peering max connections per network (default)? | 25 per VPC network by default; quota increase can be requested up to 200. Exam tip: peering is non-transitive — three peered VPCs don't automatically route between the two non-adjacent ones. |
| 2 | VPC-SC vs Firewall Rules — what layer do they protect? | VPC Service Controls operate at the API/service level to prevent data exfiltration from GCP managed services (BigQuery, GCS). Firewall rules control network traffic (IP/port) within a VPC. Exam tip: VPC-SC blocks copying data OUT even with valid IAM permissions if the destination is outside the perimeter. |
| 3 | Shared VPC: which role lets a service project deploy VMs into a host project's subnet? | roles/compute.networkUser, granted on the specific subnet (or project) to service project users/service accounts. Exam tip: this role does NOT grant ability to modify firewall rules or routes — only the host project's Shared VPC Admin can. |
| 4 | Can peered VPC networks have overlapping CIDR ranges? | No — overlapping IP ranges are not allowed and will prevent the peering connection from establishing. Exam tip: this is a common gotcha vs Shared VPC, where service projects share the SAME subnets, so overlap is never an issue. |
| 5 | Private Google Access vs Private Service Connect — key difference? | Private Google Access lets VMs without external IPs reach public Google APIs (e.g., storage.googleapis.com) via internal routing; enabled per-subnet. Private Service Connect creates a private internal-IP endpoint in your VPC to consume a specific published service (Google or third-party) across VPC boundaries, with no peering required. |
| 6 | HA VPN SLA when configured correctly? | 99.99% availability SLA, achieved using 2 interfaces on each HA VPN gateway with 2 tunnels to the peer device. Exam tip: single-tunnel configurations do not qualify for the 99.99% SLA. |
| 7 | Cloud NAT — inbound or outbound only? | Outbound-only NAT for instances without external IPs; it does NOT allow unsolicited inbound connections. It's a regional, managed resource. Exam tip: use it when private GKE nodes need internet access to pull public container images. |
| 8 | VPC Service Controls dry-run mode purpose? | Dry-run mode logs what a perimeter's rules WOULD block without actually enforcing them, letting you validate policy before going live. Exam tip: always test in dry-run before enforcing a perimeter on production traffic. |
| 9 | Dedicated Interconnect circuit capacities? | 10 Gbps or 100 Gbps per connection. Partner Interconnect ranges from 50 Mbps to 50 Gbps. Exam tip: choose Partner Interconnect when you need less than 10 Gbps or lack a colocation facility presence. |
| 10 | VPC Service Controls: purpose of ingress vs egress rules? | Ingress rules allow specified identities/sources OUTSIDE the perimeter to access protected resources INSIDE it. Egress rules allow resources INSIDE the perimeter to reach resources OUTSIDE it. Exam tip: use these to permit legitimate cross-perimeter flows without disabling protection entirely. |
| 11 | Does Private Service Connect require avoiding CIDR overlap between producer and consumer? | No — PSC only exposes a single internal-IP endpoint in the consumer VPC, so producer and consumer IP ranges never interact, unlike VPC Peering. Exam tip: PSC is the answer whenever a scenario mentions overlapping CIDRs or cross-organization private access to a service. |
| 12 | Shared VPC: who grants the Shared VPC Admin (xpnAdmin) role? | An Organization or Folder Admin grants roles/compute.xpnAdmin at the org or folder level, allowing that admin to designate host projects and attach service projects. Exam tip: this is a higher-level grant than networkUser and controls the host/service project relationship itself. |
