## Chapter 7: Encryption Everywhere: CMEK, Cloud EKM, and Confidential Computing — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Cloud KMS: minimum allowed automatic key rotation period? | 24 hours (1 day). Google's suggested default is 90 days. Exam tip: exam often tests that you CANNOT rotate more frequently than daily. |
| 2 | Cloud KMS key version destruction: default scheduled duration and configurable range? | Default 24 hours before permanent destruction; configurable window (approx. 24 hours up to 120 days) via --destroy-scheduled-duration. During this window, destruction can be canceled — after it, the key material is unrecoverable. |
| 3 | CMEK vs Cloud EKM — where does the key material live? | CMEK: key lives inside Cloud KMS (Google infrastructure), customer controls lifecycle/IAM. Cloud EKM: key lives entirely outside Google Cloud at an external partner (e.g., Thales, Fortanix); Google calls out for every operation. |
| 4 | Default Google-managed encryption vs CMEK — key management effort? | Default: always on, zero configuration, Google manages keys entirely. CMEK: customer creates/manages Cloud KMS key rings, keys, rotation, and IAM policies for full control and audit trail. |
| 5 | What does Confidential Computing (Confidential VM / Confidential GKE Nodes) protect that standard CMEK/default encryption does NOT? | Data IN USE — memory contents during active processing — via hardware-based memory encryption (e.g., AMD SEV/SEV-SNP, Intel TDX). CMEK/default encryption only protect data at rest. |
| 6 | Cloud KMS protection levels — name all four and what each means | SOFTWARE (standard software keys in KMS), HSM (Google-managed FIPS 140-2 Level 3 HSM), EXTERNAL (Cloud EKM, public internet path to external manager), EXTERNAL_VPC (Cloud EKM, private VPC path to external manager). |
| 7 | BYOK (Bring Your Own Key) in Cloud KMS — what mechanism is used to import existing key material? | An import job: customer wraps their key using an RSA-OAEP wrapping algorithm combined with AES-256 key wrap (e.g., RSA_OAEP_3072_SHA256_AES_256), then imports it into a Cloud KMS key version, preserving original key bytes. |
| 8 | gcloud command: create a Cloud KMS key with a 30-day automatic rotation period | gcloud kms keys create KEY_NAME --location=LOCATION --keyring=RING --purpose=encryption --rotation-period=30d --next-rotation-time=<timestamp> |
| 9 | gcloud command: disable vs destroy a key version | Disable (reversible): gcloud kms keys versions disable VERSION --key=KEY --keyring=RING --location=LOCATION Destroy (schedules irreversible deletion): gcloud kms keys versions destroy VERSION --key=KEY --keyring=RING --location=LOCATION |
| 10 | Decision tree: when to choose Default encryption vs CMEK vs Cloud EKM? | Default: no compliance requirement for key control. CMEK: need to control rotation/IAM/audit/disable, key can stay on Google infra. Cloud EKM: regulatory/compliance mandate that keys never leave customer's own external key management system. |
| 11 | Confidential VM hardware encryption technology — what CPU feature is used? | AMD Secure Encrypted Virtualization (SEV / SEV-ES / SEV-SNP) or Intel TDX depending on machine series selected — encrypts VM memory so even Google's hypervisor cannot read it. |
| 12 | Which encryption algorithm does Google use by default for data at rest (default encryption)? | AES-256. Applied automatically to all data at rest with no customer configuration required — foundational layer before CMEK/EKM are layered on top. |
