## Chapter 8: Cloud Storage Lifecycle and Securing AI/ML Workloads — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Max number of lifecycle rules allowed per Cloud Storage bucket? | 100 rules. Exam tip: lifecycle rules are evaluated roughly once per day, not instantly on the object hitting the condition. |
| 2 | Max retention period for a locked Cloud Storage bucket retention policy? | Up to 100 years. Once locked (Bucket Lock), the period can only be increased, never decreased or removed — enables WORM compliance. |
| 3 | Minimum storage duration before early deletion fees apply: Nearline / Coldline / Archive? | Nearline 30 days, Coldline 90 days, Archive 365 days. Deleting or reclassing sooner triggers a pro-rated early deletion charge for the remaining minimum days. |
| 4 | Event-based hold vs Temporary hold on a Cloud Storage object — key difference? | Event-based hold: releasing it STARTS the retention-period countdown (used when retention should begin at a triggering event). Temporary hold: just blocks delete/overwrite until released, no retention-clock interaction (used for litigation holds). |
| 5 | VPC Service Controls vs IAM — what's the security difference? | IAM answers 'WHO can access this resource?'. VPC-SC answers 'FROM WHERE/WHICH context can data move?' — it blocks exfiltration even with valid IAM credentials, by wrapping API access to services in a context-aware perimeter. |
| 6 | gsutil commands to set and lock a 7-year retention policy on a bucket? | `gsutil retention set 7y gs://BUCKET` then `gsutil retention lock gs://BUCKET`. Locking is irreversible — exam tests that you can only INCREASE a locked retention period afterward, never remove it. |
| 7 | How do you keep a Vertex AI prediction endpoint off the public internet? | Deploy it as a private endpoint using VPC Network Peering or Private Service Connect (privateServiceConnectConfig) instead of the default public endpoint — no public IP exposure at the network layer. |
| 8 | Architecture pattern: prevent exfiltration of Vertex AI training data and model artifacts | Place Cloud Storage, BigQuery, and Vertex AI APIs inside one VPC Service Controls perimeter; access Google APIs via restricted.googleapis.com; use Private Google Access. Blocks copy-out even with valid credentials. |
| 9 | Architecture pattern: sanitize PII before Vertex AI training | Raw data lands in a staging bucket → Sensitive Data Protection (DLP) inspect + de-identify job runs → de-identified output written to a training bucket inside the VPC-SC perimeter → training job reads only from the sanitized bucket. |
| 10 | Architecture pattern: scoping Gemini Enterprise agent grounding access | Enforce least privilege at TWO layers: (1) the agent's runtime service account IAM roles, and (2) IAM/ACLs on the underlying grounding data store (Drive, BigQuery, data store). Exam trap: agent-level config alone does not restrict data access — the data source IAM does. |
| 11 | Lifecycle condition trap: daysSinceCustomTime | This condition only fires if the object's `customTime` metadata field has been explicitly set. If customTime is never set, the rule silently never applies — a common exam gotcha for objects uploaded without custom metadata. |
| 12 | When does an early deletion fee apply for Coldline/Archive storage? | If an object is deleted OR transitioned to a different storage class before its class's minimum storage duration (Coldline 90d, Archive 365d) has elapsed, GCS bills the remaining days at that class's rate as an early deletion charge. |
